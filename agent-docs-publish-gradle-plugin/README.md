# Agent Docs Publish Plugin

This plugin packages agent-oriented documentation into a sidecar zip archive that can be resolved later and consumed locally by resolver-generated skills/resources.

The plugin contract is intentionally minimal:

- Your docs root directory must exist.
- That root must contain exactly one `SKILL.md` entrypoint file
- `SKILL.md` must start with Agent Skills YAML frontmatter and include a non-empty `description`.
- `SKILL.md` `name` value is not required, and will be generated by this plugin.
- Everything in that root directory is included in the archive. 

## What it does

- Adds a `packageAgentDocs` task.
- Wires `assemble` to depend on `packageAgentDocs`.
- Fails the build if the docs directory does not exist.
- Fails the build if `SKILL.md` is missing in docs root (case-insensitive check).
- Fails the build if `SKILL.md` frontmatter is missing or invalid.
- Fails the build if `scripts`, `references`, or `assets` exist as files instead of directories.
- Emits a warning when `name` is present and omits that field from the packaged `SKILL.md`.
- Produces an archive at:
  - `build/agent-docs/<project-name>-agent-docs.zip`
- Packages the full docs root directory contents at the zip root.
- If `maven-publish` is applied, automatically attaches the archive as an additional artifact
  with classifier `agent-docs` to all `MavenPublication`s.

## Quick start

Apply the plugin in your library project:

```groovy
plugins {
	id 'java-library'
	id 'io.github.duckasteroid.agent-docs.publish'
}
```

Create SKILL docs for your library in the default location:

```text
src/agent-docs/
  SKILL.md
  references/
    overview.md
    topics/
      getting-started.md
      troubleshooting.md
  assets/
  scripts/
```

Build your docs archive:

```bash
./gradlew packageAgentDocs
```

Or run a normal assemble build (which will include docs packaging):

```bash
./gradlew assemble
```

## Default directory layout (recommended)

The plugin defaults to:

- Docs source directory: `src/agent-docs`
- Output archive: `build/agent-docs/<project-name>-agent-docs.zip`
- Mandatory entrypoint in docs root: `SKILL.md` (case-insensitive in source)
- Mandatory frontmatter field in `SKILL.md`: `description`
- Zip structure mirrors docs root contents
- The entrypoint is always written to the zip as `SKILL.md`

## Validation rule controls

`validateAgentDocs` runs a composite set of rule classes. You can skip specific rules:

```groovy
agentDocs {
  disabledValidationRules = ['skill-name', 'skill-compatibility']
}
```

You can also disable rules from CLI:

```bash
./gradlew validateAgentDocs -PagentDocs.disabledValidationRules=skill-name,skill-compatibility
```

Supported rule IDs:

- `docs-directory-exists` — ensures the configured docs directory is present.
- `skill-entrypoint` — requires exactly one root-level `SKILL.md` entrypoint (case-insensitive).
- `standard-directories` — verifies `scripts`, `references`, and `assets` are directories when present.
- `skill-frontmatter-structure` — checks that `SKILL.md` starts with valid YAML frontmatter delimiters.
- `skill-description` — requires a non-empty `description` frontmatter field with valid length.
- `skill-name` — warning-only rule that reports publisher `name` is ignored because resolver naming is authoritative.
- `skill-compatibility` — validates optional `compatibility` frontmatter length when provided.
